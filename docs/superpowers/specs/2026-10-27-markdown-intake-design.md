# FR-008 Markdown intake

Deliver MZ-008 as the first end-user intake feature in M-02. The all-ticket instruction delegates routine implementation choices; no real organization data is imported or published by development. Read docs/intake-storage.md for the retention/promotion policy established before code changes.

## Approach

Keeping only a file reference would lose stdin and make recovery depend on mutable original paths. Putting arbitrary raw text or a derived summary in SQLite conflicts with the established structural/credential boundary. Use exact private source copies outside Git plus structural SQLite intake metadata. Retain copies until explicit operator removal, without automatic deletion. No proprietary encrypted source format, remote storage, scheduler or publication workflow is introduced.

Core `ingestMarkdown({state, sourceDirectory, actorId, scope?, source})` accepts source `{type:'file', path}` or `{type:'stdin', stream:AsyncIterable<Uint8Array>}`. Trusted stream code may yield untrusted bytes; it is not a sandbox for hostile iterator code. Validate options/state/UUID/scope first. Accept nonempty valid UTF-8 without NUL, at most 1 MiB; preserve exact bytes including BOM/newlines. Read regular non-symlink files through O_NOFOLLOW|O_NONBLOCK and a bounded descriptor read; reject pipes/devices/directories and oversize/invalid input. Stream bytes are bounded; EOF is required, with normal CLI interruption for an unfinished producer.

Scopes are unclassified (default), company, project-candidate, or project:<id>, where id is a 1–64 character lowercase letter-leading ASCII slug of letters/digits/hyphen. Scope is metadata, never a project activation or capability. The actor is an explicit stable UUID, not an arbitrary creator name.

Verify a configured private absolute source directory with shared host rules, then reject any Git working-tree/bare repository ancestor (including .git files used by worktrees). Create a new exclusive UUID directory, durably write 0600 content.md and metadata.json, synchronize the directory/root, then create the inbox record, intake metadata and inbox.created event in one Core transaction. On failure remove only the owned source directory and throw a static safe IntakeError; source content, file names/paths and caught exceptions must not reach reports. A crash before SQL commit may leave an orphan with a manifest for manual reconciliation; there is no false claim of cross-store atomicity. Original source files are never modified.

Migration 003 adds inbox_intake keyed by existing inbox_items.id: source_type(file/stdin), source_bytes(1..1048576), scope, created_by actor UUID and summary_status fixed pending. Existing tables/data and migration 001/002 remain unchanged. Existing structural inbox records may lack intake metadata. Extend createInboxItem with optional nested intake fields and getInboxIntake for typed reads; preserve existing InboxItem shape. Atomically validate/store optional metadata before the automatic created event. The Core result includes item, intake metadata, summary placeholder and untrusted:true, without raw text/path/name.

CLI: `mz ingest FILE` or `mz ingest -`, requiring a valid company selection, an explicit existing runtime database, a private source directory and actor identity. Use flags --company/--runtime/--source-directory/--actor/--scope/--json, with MZ_COMPANY_DIR/MZ_RUNTIME_DB/MZ_SOURCE_DIR/MZ_ACTOR_ID environment fallbacks. Runtime must exist: refuse accidentally initializing the wrong store; normal Core opener may apply supported migrations after explicit selection. Validate CLI settings before source reads; parse errors return 2 without echoing rejected arguments, input/access/state failures return 1 with a static message, success returns 0 and generated identities/structural metadata only. Stdin is streamed, not eval'd or front-matter interpreted. Help/version remain configuration independent.

## Verification

File/stdin byte preservation and source metadata; all scopes; no Markdown instruction execution/provider/LLM calls; no content/name/path in SQLite/events/CLI/error; ownership/mode/Git-root protections; missing/pipe/symlink/oversize/invalid UTF-8/NUL input; atomic inbox/metadata/event rollback and owned cleanup; true migration-v2 upgrade preserving backup/inbox/event data; previous state/snapshot/doctor behaviors; clean install CLI from unrelated directory. Full check/typecheck, independent review and exact-head CI before merge. No actual data import or live backup/provisioning is performed.
