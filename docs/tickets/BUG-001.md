# BUG-001 — Explain GitHub access and offer scoped token setup before OAuth

## Reproduction and actual behavior

During actual owner setup, `mz init` delegates a failed private GitHub clone to GitHub CLI browser/device-code login with no preceding identity, repository or permission explanation. GitHub CLI requests its broad baseline OAuth scopes. The owner cannot choose an organization/repository-scoped fine-grained credential or see suggested membership permissions. This was confirmed by the current init source/native argument tests and the owner identifying the screen as GitHub.

## Expected behavior

Explain GitHub separately from Codex. Recommend a fine-grained GitHub token for the selected organization/repository, describe minimum initial and optional later permissions, and accept it through hidden terminal input or a protected-file reference. No token is passed in argv, model context, logs, Git or SQLite. Retain explicitly chosen browser OAuth/existing credentials, with broad scope and restricted-member guidance before launching. Signing in must not claim to create membership or grant organization authority.

## Scope and references

- Owner report during real onboarding; generic implementation correction under M-05.
- [First use](../getting-started.md), [secret boundary](../secrets.md).
- [GitHub CLI authentication](https://cli.github.com/manual/gh_auth_login), [fine-grained tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).
- Use an MZ-specific native GitHub CLI credential profile so the selected token is authoritative for MZ without replacing unrelated personal credentials. Persist only profile references in local Git configuration, never credentials in company knowledge. Codex/ChatGPT authentication remains separate.

## Acceptance

- [ ] Identity/repository/scope/membership explanation precedes any new GitHub login, and OAuth is never the implicit fallback.
- [ ] Fine-grained token setup works without OAuth using hidden input or protected-file reference; no key argument or unintended credential output/global model environment exposure.
- [ ] Existing Git/auth workflows and explicit automation remain available; selected MZ GitHub credentials are reused by company Git and the interactive steward without replacing unrelated personal profiles.
- [ ] Synthetic native-client/CLI tests, masked-input verification, full checks, review and installed verification are recorded. No live authentication/account grants/revocations are performed by development.

## Verification and limitations

Registered before implementation. The owner may cancel the old device-code prompt; the running process is not interrupted by development tools. Actual granted permissions remain GitHub-enforced; successful connection must not be advertised as proof of every optional write capability.

Implemented the scoped native-client profile, hidden/protected-file token entry, explicit OAuth/existing choice, concrete identity/resource/permission text, separate Codex explanation, scoped Git helper references and steward/doctor propagation. Existing company selection/remote is checked before credential changes. Core host-directory validation prevents credential profiles/source files under Git or company knowledge; provider-store aliases are rejected before entry.

Observed RED/GREEN tests cover the original implicit OAuth behavior, token stdin/no-argv handling, profile-only model environment, real Git credential transport under paths with spaces/apostrophes, ambient-token removal, local helper idempotence, source-file flow, provider-store link rejection and doctor identity-profile consistency. A real PTY test verified no typed-token echo; a second test rejected oversized unterminated input without echo. Full check/typecheck and final independent review evidence follow. No live authentication, membership change, grant/revocation, token creation or model call was performed by development.

Before independent review: `npm run check` passed 430/430 tests plus build/lint/format; `npm run typecheck`, whitespace and changed-document links passed. Actual credential scope/grants are GitHub-enforced; tests use only synthetic provider clients/tokens and isolated directories.
