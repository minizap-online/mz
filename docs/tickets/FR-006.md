## Verification and limitations

Implemented 2026-10-27 on `fr-006-provider-abstractions`. Core owns provider-neutral references, repository/work-item DTOs, SourceControlProvider/WorkProvider, action identities, a structural audit sink contract, and source-safe ProviderError. The GitHub package depends on Core and supplies an offline skeleton; no vendor SDK objects enter the domain.

Verification: 16 new runtime tests first failed against the absent API, then passed. A compile-time fixture verifies neutral DTO compatibility and rejection of vendor response shapes, invalid reference kinds, missing failed-audit codes, and request content in audits. Clean-install coverage imports the GitHub package from an unrelated directory. `npm run check` passed all 211 tests, build, lint and format; `npm run typecheck`, local Markdown links and `git diff --check` passed. Independent review found no critical, important or minor findings; reviewer independently passed 17 provider tests plus the clean-install test. PR/CI/merged-main verification follows before Done.

The skeleton validates scoped identities, records acknowledged started/failed audit phases, withholds request content/URLs, sanitizes sink exceptions, and returns NOT_IMPLEMENTED. It makes no network call, resolves no credentials, and implements no successful remote action. The host must provide a genuinely durable sink; no production audit sink or live provider integration is provisioned. Future real writes require capability enforcement and deliberate sanitized promotion. See [provider contracts](../providers.md).
