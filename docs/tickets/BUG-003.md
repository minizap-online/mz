# BUG-003 — Use a public inactive webhook URL in the GitHub App manifest

## Reproduction and cause

Actual owner onboarding reached GitHub's manifest registration form. GitHub rejected hook_attributes.url because localhost is not publicly reachable, despite active:false. MZ supplies a dummy loopback webhook endpoint even though no webhook/event receiver is implemented or needed by this pilot flow.

## Expected behavior

Generate a manifest with webhooks explicitly disabled, no event subscriptions and a valid public placeholder URL for GitHub validation, retaining loopback browser redirects and existing owner-access restrictions. The existing public MZ homepage is used rather than exposing a receiver or forwarding private callbacks to a third-party service. A registration rejected by GitHub before App creation can be retried through MZ after the owner confirms that rejection; uncertain conversions still require recovery/import rather than duplicate registration. Never clear pending key/connection files or broaden grants during this retry.

## Acceptance

- [x] Actual served manifest sets hook_attributes.active=false, uses the public MZ homepage rather than localhost, and subscribes to no events; owner/permission protections remain unchanged.
- [x] Confirmed form rejection can restart from saved technical organization/owner selection without deleting credentials; default/no confirmation preserves the intent and requires recovery.
- [x] State/Host/replay and successful conversion tests remain green; full checks, review and installed verification recorded. Actual GitHub registration acceptance remains owner-run live evidence.
