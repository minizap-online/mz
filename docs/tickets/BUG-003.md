# BUG-003 — Use a public inactive webhook URL in the GitHub App manifest

## Reproduction and cause

Actual owner onboarding reached GitHub's manifest registration form. GitHub rejected hook_attributes.url because localhost is not publicly reachable, despite active:false. MZ supplies a dummy loopback webhook endpoint even though no webhook/event receiver is implemented or needed by this pilot flow.

## Expected behavior

Generate a manifest with webhooks explicitly disabled, no event subscriptions and a valid public placeholder URL for GitHub validation, retaining loopback browser redirects and existing owner-access restrictions. The existing public MZ homepage is used rather than exposing a receiver or forwarding private callbacks to a third-party service. A registration rejected by GitHub before App creation can be retried through MZ after the owner confirms that rejection; uncertain conversions still require recovery/import rather than duplicate registration. Never clear pending key/connection files or broaden grants during this retry.

## Acceptance

- [ ] Actual served manifest sets hook_attributes.active=false, uses the public MZ homepage rather than localhost, and subscribes to no events; owner/permission protections remain unchanged.
- [ ] Confirmed form rejection can restart from saved technical organization/owner selection without deleting credentials; default/no confirmation preserves the intent and requires recovery.
- [ ] State/Host/replay and successful conversion tests remain green; full checks, review and installed verification recorded. Actual GitHub registration acceptance remains owner-run live evidence.

## Verification

Registered before implementation. Owner reported explicit GitHub invalid-manifest validation; no App creation occurred in that rejected submission. Current live init/tunnel is not interrupted by development. GitHub's manifest reference requires a URL inside hook_attributes; the inactive placeholder pattern avoids relying on unspecified omission defaults: https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest .

Observed RED/GREEN verifies the actual setup notice, public inactive webhook/no-event manifest, and confirmation-gated rejected-form retry. Negative tests preserve uncertain intent; destination overrides are validated/quoted, custom HTTPS origins do not get an incompatible tunnel command, and browser/devbox ports can differ. Full check passed 477/477 tests plus build/lint/format; typecheck passed. One final independent review and delivery remain. No live registration, tunnel or owner process changed during development.
