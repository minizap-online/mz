# BUG-005 — Keep owner conversations within company control responsibilities

## Reproduction and expected behavior

An interactive owner conversation interprets a project request as permission to build application source inside the company repository. The launcher makes the company checkout writable but does not give Codex a direct controller instruction separating curated company knowledge from project implementation.

Company purpose, infrastructure context, policies, decisions and project references belong in the company repository. Project application source, dependencies, tests, CI and deployment configuration belong in dedicated project repositories and workspaces; actionable work belongs in their issue trackers. Company project directories may retain curated briefs, architectural context, decisions and linked status summaries.

## Acceptance

- [x] Both guide and ask pass a shared company-control policy directly through Codex developer instructions and include it in printable private assignments.
- [x] The policy routes authorized repository creation/attachment through existing MZ commands, uses explicit target repositories for issue work, and explains the missing worker launcher instead of writing fallback implementations in company directories.
- [x] Mode-specific guide/steward instructions and read-only mode remain intact; private questions/context do not enter process arguments.
- [x] Tests and docs state the limitation: this is trusted-host behavioral guidance, not per-file sandbox enforcement or a delivered worker engine.
- [x] Existing active owner conversations and company files remain untouched.
