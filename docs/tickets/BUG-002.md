# BUG-002 — Accept GitHub SSH repository URLs in App onboarding

## Reproduction and cause

Owner runs mz init, enters git@github.com:OWNER/company.git and chooses the recommended App method. Repository input validation accepts this URL, but the App branch later requires an HTTPS prefix and throws before registration. The generic error still recommends personal tokens rather than explaining App setup. Source inspection confirms this exact path.

## Expected behavior

App setup accepts the normal GitHub SSH clone URL and explicitly uses the equivalent HTTPS repository for installation-token authentication. Existing SSH/HTTPS origins for the same GitHub repository are recognized; only a verified same-repository checkout is rebound to HTTPS for App mode. Foreign/conflicting origins fail before credential changes. Explicit existing/OAuth SSH behavior remains available. Failure guidance identifies the setup stage and App recovery path without raw provider errors, credentials or private paths.

## Acceptance

- [ ] RED/GREEN regressions reproduce the reported interactive path, clone normalization, existing origin transition and rejection of a different repository.
- [ ] New and existing App checkout operations use HTTPS and App credentials; no SSH key or personal-token fallback.
- [ ] Source-safe stage guidance replaces irrelevant token-only failure advice.
- [ ] Full checks, independent review, exact-head CI and installed devbox verification recorded; no actual owner registration/credentials/checkout modified by development.

## Verification

Registered before code changes. Scoped M-05 onboarding bug; no new credential authority or schema change. GitHub documents installation-token Git access over HTTP(S): https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation .

Observed RED: reported interactive SSH/App path never reached the organization question; fresh clone and existing-checkout cases failed before App access. GREEN: SSH input reaches App setup, clone/read use HTTPS, and existing fetch/push URLs become HTTPS only after same-repository checks. Foreign fetch/push targets reject before any provider request. Generic failure now names a fixed source-safe stage and App recovery guidance. Full check passed 471 tests plus build/lint/format and typecheck; independent review and delivery follow. No live setup, credentials or actual owner checkout changed.
