# FR-015 — Connect an organization-owned GitHub App and provision projects without owner lockout

## Outcome

Replace repeated personal-token setup with one organization-owned App connection, automatic bounded installation credentials and owner-guided project provisioning through MZ. Preserve the human owner's GitHub access independently of MZ.

## Scope and references

Owner selected the organization-owned GitHub App approach, organization-wide access including future projects, and explicitly required that the App cannot reduce the owner's permissions. [Design](../superpowers/specs/2026-10-28-github-app-owner-access-design.md). Builds on FR-014/BUG-001 and the implementation plan's preferred short-lived project credential model. Scoped M-05 onboarding/website-pilot support; generalized worker scheduling remains M-06.

## Dependencies

Design approved and merged as PR35; [implementation plan](../superpowers/plans/2026-10-28-github-app.md). Actual GitHub registration/installation needs the owner's signed-in GitHub approval. No existing personal token may be used to manufacture authority for the App.

## Acceptance

- [x] Init prepares the actual connection/permission suggestion, registration and installation flow; resume and explicit PAT/existing compatibility remain supported.
- [x] GitHub grant excludes Members write, organization Administration write, repository Administration write and user authorization; protected owner membership is verified read-only and failures never trigger privilege expansion.
- [x] Owner retains direct GitHub control of the organization, App registration and installation; no app operation can change owner identity/membership or broaden its own grant.
- [x] Core/provider boundary validates operation/project authority and issues explicit short-lived repository/permission subsets without exposing App keys or broad credentials to workers.
- [x] Owner-approved website project provisioning creates/attaches a repository and records durable knowledge/provider references with retry/recovery and audit semantics, without a new personal token.
- [x] Tests cover denied owner changes, excessive grants, credential narrowing, recovery/redaction and no ambient fallback; live grant/read/provisioning checks are distinguished from fixtures.
