# CR-002 — Clarify GitHub work authority and runtime state boundary

## Outcome

The plan listed runtime inbox records without explicitly separating them from the GitHub work queue. GitHub Issues and Projects own actionable work, priority, milestone, and board status. Git repositories own curated knowledge. SQLite holds execution history and references behind Core; it must not become a competing editable task tracker.

## Scope and references

User clarification and authorization on 2026-10-27; docs/workflow.md; MZ_IMPLEMENTATION_PLAN.md section 5. Document the boundary during M-00; implement integrations in their scheduled milestones.

- [x] Explain private intake and explicit promotion/linking to actionable issues.
- [x] Preserve runtime history and human project activation requirements.
